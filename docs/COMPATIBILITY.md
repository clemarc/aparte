## Protocol to validate an adapter

Use disposable documents/drafts. Never send a message or test destructive commands. Capture target app version, macOS major.minor, method, produced transcript (synthetic only), exact resulting text and clipboard types/change behavior. Each target needs ten attempts covering: caret at end, caret mid-paragraph, selection replacement, accented French, non-BMP emoji, rich surrounding text, rapid Escape, app switch and return to original field, original window/field mutation, and concurrent clipboard copy. Happy paths must insert exactly once without surrounding loss or submission; safety refusals must insert nothing. An app switch alone is now an intended D021 happy path only when the original field remains valid and is brought foreground again. Safety refusal is not a happy-path pass.

Test AX API success against actual visible content; after an ambiguous write, verify no clipboard fallback. For paste, test one-second restoration, including a deliberately slow consumer. Slow/custom consumers that lose text must receive an explicit scoped refusal; merely removing an override does not disable the generic route. Terminal must retain text as inert unsubmitted input; a custom paste handler may execute text and is outside Aparté’s guarantee. Remote desktops, password managers and elevated prompts are unsupported.

Only after evidence passes add the exact appVersion/osVersion and tested roles/method to `validated`. Keep overrides appropriately scoped and add explicit refusals when unsafe behavior is confirmed. Recovery retains one backup after attempted insertion because the OS does not acknowledge consumption; its reason distinguishes attempted paste from refusal. Check the target before manually copying again.

## Clipboard behavior and evidence

D013 supersedes D008's empty/known-eager-only restriction. Snapshots may request ordinary foreign provider data. All original representations must be preserved within 8 MiB/500 ms; explicit promise/lazy-marker formats, absent data, oversized contents, timeout or ownership change refuse automatic paste. The limit bounds accepted snapshot bytes, not the peak allocation of an individual native read. A timed-out native read cannot be cancelled; one worker stays busy until it unwinds, and late completion cannot write.

Real isolated named-pasteboard tests exercise a separate foreign owner of text/RTF/PNG/multiple items, a fast lazy provider, and a slow provider. Original bytes plus extra AppKit text encodings are retained and restored after the owner process exits. Additional tests cover empty boards, concurrent new copies, snapshot-to-write races, unsupported promise formats and oversized data. They never touch the user's general clipboard and do not post paste events to a real app. See `docs/evidence/clipboard-fix.json` for final results.

Restoration occurs one second after dispatch, only with matching changeCount/marker/text, unless D022's owner-requested Recovery handoff retains the transcript on the clipboard. Newer copies are preserved and not read. On a non-attempted insertion failure the Recovery transcript intentionally replaces prior clipboard data. No atomic cross-process compare-and-swap or universal paste acknowledgment exists. Orderly quit/cancel tries conditional restoration outside Recovery; crashes cannot guarantee it. Provider reads may trigger work in another app or Universal Clipboard. Full target paste/consumption remains an independent BLOCKED gate.

Foreground apps are asked through the documented AXManualAccessibility setter to expose their accessibility tree when Aparté already has AX trust; unsupported setters fail without changing macOS permissions. This does not read surrounding text or set focus. Custom/inaccessible controls, remote desktops and elevated prompts have no universal compatibility guarantee.

In 0.4.8 the AXManualAccessibility setter is attempted directly for an already AX-trusted foreground app because some apps do not accurately advertise it as settable. If application and system focus links are absent, Aparté checks the active AX window for a unique focused standard text control within a 96-node, 10-level, 300 ms limit. A missing window, no unique match or elapsed limit refuses insertion. No full text value or document title is read. The owner must retry ChatGPT; the observed 0.4.7 failure does not establish that the new fallback succeeds.

Version 0.4.10 requests Chromium web accessibility only for foreground app bundles with a Chromium runtime marker, once per process; Chromium may take about two seconds to expose the full web tree. This changes that app's accessibility mode, not macOS permissions. If direct focus remains absent, a left click in a text input within the previous ten seconds, without intervening ordinary key input, may provide a hit-tested field in the same active window. The field must have positive editability evidence and pass every original context guard, and it is hit-tested again before insertion. A click on a non-text, secure or read-only control uses Recovery. The owner reports native controls working but webpage fields failing before this version; live web insertion remains BLOCKED.

Version 0.4.11 permits consulting another app while dictating. Once transcribed, Aparté requests a return to the captured original app/window/field; it does not direct Cmd-V to a background process. Insertion requires the same foreground process, AX window/element, editability and selection, with a short focus-settle period. If the app/window cannot be returned or the field is not provable within two seconds, Recovery receives the transcript and puts it on the clipboard for manual paste when Aparté still owns the board. Real activation and webpage focus remain BLOCKED; do not mark a browser adapter validated from source checks.
